Critérios para decidir
Consistência metodológica

Conjunto “antigo/novo” segue um padrão PPBio formal (TN/TS/TL/TW + distância + módulo + T/R + índice).
Códigos como T1–T10, R1–R3, TL3500_PSA2, TW065_RIP5_PSA9 parecem de campanhas locais ou variações (PSA, RIP extras).
Semântica dos códigos

Misturar códigos heterogêneos sem campos explicativos gera ambiguidade analítica (comparações, estatísticas de instalação).
Separar mantém clareza entre rede padrão e parcelas complementares.
Manutenção futura

Um único arquivo unificado é mais simples de carregar no dashboard, mas só se tiver colunas que explicam origem e tipo detalhado.
Dois arquivos (ou uma coluna de filtro robusta) facilitam auditoria e evita “poluição” de análises oficiais.
Integração espacial e visualização

Para o mapa, usuários querem “ver tudo”; para análises, talvez apenas o conjunto oficial.
Camadas/filtros resolvem isso facilmente se houver um campo de classificação.
Recomendações
Opção recomendada: Integrar em uma tabela única, mas com novos campos para preservar a separação lógica.
Sugestão de novas colunas:

origem: valores (“PPBio_oficial”, “Complementar_local”)
padrao_ppbio: boolean (True se segue estrutura antigo/novo reconhecida)
codigo_bruto: o código original do layer de coordenadas (ex.: TW065_RIP5_PSA9)
base_ppbio: a parte “normalizada” quando houver (ex.: TW065).
observacoes: livre para anotar PSA, múltiplos RIP, etc.
Por quê essa opção?

Evita divergência incremental entre dois arquivos (sincronização).
Facilita filtros no dashboard (checkbox “Mostrar apenas PPBio oficial”).
Permite exportar tudo de uma vez (CSV/XLSX/GeoJSON) mantendo rastreabilidade.
Futuras análises podem excluir complementares apenas com um WHERE origem = 'PPBio_oficial'.
Quando manter separado?

Se ainda há incerteza sobre a validade ou permanência dos códigos complementares.
Se o conjunto extra é provisório ou sujeito a grande revisão.
